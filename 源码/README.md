# 豆包语音 Win 桥接

- 单独长按 Win：直接调用豆包 ImeService 的语音 RPC，松开后把识别文本写入原光标位置。
- 长按右 Alt：可使用相同的独立语音输入；默认与长按 Win 同时启用。
- 短按 `Win`：正常打开开始菜单。
- `Win+E`、`Win+R` 等：保持原有 Windows 快捷键行为。
- 托盘图标右键可以打开设置、暂停或退出。

设置窗口可以分别开关 Win、右 Alt，调整长按触发时间，并配置豆包输入法安装目录。
程序首次启动时会依次从正在运行的 `ImeService.exe`、卸载注册表和默认安装位置自动探测目录；
通常不需要手工填写。探测失败时，可以在托盘菜单的“设置...”中点击“自动探测”或“浏览...”。

当前测试版启动语音时不再调用 `RpcPipe_FocusIn` 或发送 `Activate` 消息，
保留语音开始、显示、停止和文字提交流程。调用前记录具体 TSF 输入法 profile，
识别结束、取消、RPC 失败或正常退出时尝试归还；不把所有中文输入法都视为同一个键盘布局。
快照和归还前的状态读取使用一次性 STA 线程，避免常驻 RPC 线程保留旧的输入法状态。
仅当原窗口仍在前台、当前输入法是豆包且与原输入法不同时归还。
离开原窗口，或改选其他非豆包输入法时跳过；主动改选豆包与语音自动切换无法区分。
归还使用当前桌面作用域，也可能改变其他窗口的输入法选择；不修改默认输入法设置。
强制结束进程无法保证归还。实际效果以语音结束后键盘输入时的候选框为准；
不能仅凭任务栏图标或 TSF profile 日志判定。

本轮测试：先选搜狗，分别用长按 Win、右 Alt 完成语音输入，再用键盘输入拼音，
确认语音文字正常写入且候选框仍属于搜狗；每种触发键连续测试 2～3 次。

本机的跨进程 profile 对照、取消、退出、失败清理和连续会话测试见 [tests/README.md](tests/README.md)。
这些检查不替代真实语音落字及键盘候选框验收。

分发给其他用户时只需提供整个 `VoiceWinBridge` 目录并运行 `install.ps1`，不需要安装 Python。

安装或重新启动登录自启（使用发布包中已经编译好的 EXE，不会在用户电脑上编译）：

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

只有修改源码后制作发布版时才需要运行 `build.ps1`。

移除登录自启并停止程序：

```powershell
powershell -ExecutionPolicy Bypass -File .\uninstall.ps1
```
